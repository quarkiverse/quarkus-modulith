The finest events to publish: `seconds`, `minutes`, `hours` or `days`. Every granularity includes the coarser ones, so `hours` publishes hourly and daily events (plus the weekly, monthly, quarterly and yearly ones derived from the days). Decides which scheduler jobs are registered at startup and how `TimeMachine.shiftBy` steps through time. Spring Modulith: `spring.modulith.moments.granularity`.

[.description]
--
The locale that defines the first day of a week and the week numbering, for example `en-US` (weeks from Sunday to Saturday) or `de-DE` (ISO weeks from Monday to Sunday). Defaults to the default locale of the JVM, which a native executable fixes at build time, so set it explicitly. A native executable only has the data of the locales listed in `quarkus.locales` (by default the locale of the build machine): add this locale there, for example `quarkus.locales=en-US,de-DE`. The extension logs a warning at startup when the locale is not available. Spring Modulith: `spring.modulith.moments.locale`.

[.description]
--
Whether this instance registers the scheduler jobs that publish the events. Every instance with the jobs publishes every event, so with several instances of the application each event arrives once per instance. Set it to `false` on all instances but one (for example with the environment variable `QUARKUS_MODULITH_MOMENTS_JOBS_ENABLED=false`), or make the listeners idempotent. The time machine works either way. Quarkus extra.
